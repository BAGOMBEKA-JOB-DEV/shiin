## Areas

These areas exist so that responsibility can be split as maintainers join.
Until then, all of them belong to the founding maintainer.

| Area | Covers |
|---|---|
| Specifications | `docs/spec/`, schemas, test vectors |
| Security | `docs/security/`, threat model, vulnerability handling |
| Engine | Evaluation, policy, classification, intent, risk |
| Adapters | Host integrations and the MCP proxy |
| Documentation | Everything else under `docs/`, the style guide, the checks |
| Release | Versioning, release engineering, supply chain |
