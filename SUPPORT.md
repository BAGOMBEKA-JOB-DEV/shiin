# Support

Shiin is experimental; source builds and published alpha releases are supported on a best-effort basis.
Questions and reports about the implementation, integrations, and design are welcome.

## Where to go

| What you need | Where |
|---|---|
| A question about the design or the documentation | Open an issue using the documentation or specification form |
| A problem in a specification, such as ambiguity or a contradiction | The specification feedback issue form |
| A missing capability or use case | The feature request issue form |
| Support for another agent or host | The integration request issue form |
| A suspected way to bypass Shiin's decisions | Follow [SECURITY.md](SECURITY.md); never a public issue |
| A larger design change | Read the [RFC process](docs/rfcs/README.md) first |

Use the issue forms for open-ended questions as well; a separate discussion service is not required.

## Before asking

- [Documentation home](docs/README.md) explains what exists, what is specified, and what is only planned.
- [FAQ](docs/overview/faq.md) answers the most common questions.
- [Roadmap](docs/project/roadmap.md) says which milestone delivers what.
- [Limitations](docs/concepts/limitations.md) is the honest account of what Shiin cannot do.

## Response expectations

Shiin is maintained by volunteers, and there is no commercial support.
Security reports follow the timelines in [SECURITY.md](SECURITY.md).
Other issues are answered as time allows.
