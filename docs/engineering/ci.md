# Continuous integration

> [!NOTE]
> **Project policy: draft.**
> This page is the only home of Shiin's CI rules.

## Workflows

| Workflow | When it runs | What it does |
|---|---|---|
| `ci.yml` | Pull requests and pushes to `main` | Formatting, lints, and tests on each platform tier; release latency measurements on Linux and macOS; isolated engine WebAssembly check; the minimum supported Rust version; `cargo deny`; and a check that every action is pinned by commit |
| `docs.yml` | Pull requests and pushes to `main` | `cargo xtask docs-check`, intent measurements, engine dependency check, the mdBook build, links, spelling, and Markdown lint |
| `robustness.yml` | Pull requests and pushes to `main` | Bounded parser fuzzing and pure wire-type tests under Miri on a dated nightly |
| `release.yml` | A `v*` tag | Builds every target, produces archives, checksums, and installers, attests build provenance, and publishes the release. Generated by dist, so it is not edited by hand |
| `sbom.yml` | A `v*` tag | Produces the CycloneDX bill of materials and attaches it to the release |

Tests run on Tier 1 platforms as a blocking check, and on Tier 2 without blocking; see
[platform support](../reference/platform-support.md).

## Permissions

The `docs` workflow has read-only `contents` permission and does not persist checkout credentials.

## Regenerating the release workflow

`release.yml` is generated by `dist generate`, which writes action references as tags. The
project requires commit pins, so after regenerating it, re-pin the references and check the
result:

```console
$ dist generate
$ grep -nE 'uses: [^@]+@v[0-9]' .github/workflows/release.yml
```

The `ci.yml` pin check fails the build if any reference is left on a tag or a branch, so a
regeneration cannot quietly undo this.

## Third-party actions

Third-party actions are pinned by commit SHA, with the release tag in a comment.

## Nightly jobs

Nightly jobs use a dated nightly named in the workflow, updated by pull request.
